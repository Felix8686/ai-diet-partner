## ChatGPT 第四次复验：唯一合并前语义修正已完成

前三次复验发现的问题已经确认修正。本轮唯一的首页语义问题已修正并通过验证，当前不再扩大 Round 03 范围，等待 ChatGPT 做最终合并判断。

### “通常不吃早餐”时，首页仍把早餐显示成“缺少方案”

规划器现在会根据 `breakfastPattern = 通常不吃` 正确地不生成早餐，这是对的。

但 `components/home-screen.tsx` 目前只看到“当天没有 breakfast”，无法区分：

1. 因用户明确选择“通常不吃早餐”而主动不安排；
2. 因严格约束导致早餐模板真的无法生成。

因此在早晨，用户明明告诉系统自己通常不吃早餐，首页仍会显示：

`早餐暂时没有合适模板，先看其他餐别。`

同时顶部仍显示“先看早餐”。这会把用户主动选择错误地表现成系统失败，也违背“适应用户现实”的产品原则。

要求做最小修正：

- 首页能够知道用户是否选择“通常不吃早餐”。
- 如果是用户主动选择通常不吃早餐：
  - 早晨不要显示“早餐暂时没有合适模板”。
  - 不要继续用“先看早餐”作为顶部提示。
  - 应直接把午餐视为下一顿主要信息；午餐存在时作为早晨的 focus 内容。
  - 不增加“早餐很重要”“建议吃早餐”等健康说教。
- 如果用户本来会吃早餐，但因为条件/禁忌导致早餐确实无可行模板，则继续保留当前轻量 `MissingMeal` 提示。
- 不要为此重构整个首页；读取已保存 profile 或增加一个很轻量的计划状态字段均可，选择更简单可靠的方案。

### 验收

至少增加测试或可验证 smoke，证明：

1. `breakfastPattern = 通常不吃` + 早晨：不出现“早餐暂时没有合适模板”，午餐成为主要下一顿。
2. 正常早餐用户但早餐确实无可行模板时，缺失提示仍能正常出现。
3. `npm run lint`、`npm test`、`npm run build` 全部通过。
