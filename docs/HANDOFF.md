## ChatGPT 第三次复验：仍有 3 项合并前问题

PR #3 目前仍不要合并 `main`。本轮只修以下问题，不进入 Round 04，不接任何外部服务。

### 1. 用户按界面示例填写“对 X 过敏”时，禁忌过滤可能失效

当前 `lib/meal-planner.ts` 的 `terms()` 会删除“过敏”等词，但会把：

`对鸡蛋过敏`

处理成：

`对鸡蛋`

随后使用简单字符串包含判断时，模板中的“鸡蛋 / 茶叶蛋”不会匹配“对鸡蛋”。

而建档页面 `饮食禁忌` 的 placeholder 正在引导用户填写“对花生过敏、素食”。因此这是实际输入路径，不是理论边缘情况。

要求：

- 让当前 UI 推荐的自然中文输入方式可以正确工作。
- 至少正确处理 `对鸡蛋过敏`、`对牛奶过敏` 这种“对 X 过敏”格式。
- 不需要实现 NLP；使用简单、可测试的规范化即可，例如去除过敏表达中的前缀“对”。
- 主方案与替换方案必须同时遵守修正后的禁忌结果。
- 增加自动测试：`dietaryRestrictions: "对鸡蛋过敏"` 时，主方案和替换方案均不得出现鸡蛋、茶叶蛋等蛋类模板。

### 2. `breakfastPattern` 已让用户填写，但规划器实际上完全不使用

建档明确询问：

- 大多数时候会吃
- 有时来不及
- 通常不吃

但当前 `generateWeekPlan()` 每天固定规划 `breakfast + lunch + dinner`，因此用户选择“通常不吃”后仍会得到 7 天早餐安排。

这违反产品核心原则：优先适应用户现实，而不是要求用户适应计划。

Round 03 使用最简单规则修正即可：

- `通常不吃`：不要强制生成每日早餐；当前 MVP 可直接不安排早餐。
- `有时来不及`：早餐优先选择无需烹饪或非常快的方案；不要为了丰富度强行安排复杂早餐。
- `大多数时候会吃`：保持现有正常早餐规划。
- 不要加入“必须吃早餐”式提醒或健康说教。
- 增加自动测试，证明至少“通常不吃”和“有时来不及”会真实改变早餐结果。

### 3. 建档暴露“自己带饭”选项，但模板和规划逻辑没有真正支持它

`app/onboarding/page.tsx` 当前让用户选择 `自己带饭`，但现有餐食模板没有对应场景，规划器也没有对它做映射或偏好处理。

因此用户如果把“自己带饭”作为主要场景，这个选择基本不会改变午餐结果。

要求：

- 不要保留一个看起来可用、实际上没有效果的建档选项。
- 优先保留这个场景并做一个最小可用实现，因为它符合目标用户的现实饮食环境。
- 可以复用适合提前制作/携带的家庭午餐模板，不需要建立复杂便当系统。
- 生成的午餐应能明确体现“自己带饭”这一场景，并且相应食材进入采购清单。
- 如果在当前模板池无法可靠实现，则暂时从 onboarding 隐藏该选项也比保留无效选项更好，但必须在交接文档说明选择。
- 增加测试：以 `mealScenes: ["自己带饭"]` 为主要场景时，工作日午餐结果必须与普通食堂/外卖画像有可验证差异，并且采购语义正确。
