## ChatGPT 本轮复验结论

Round 03 的总体架构和数据闭环方向正确，但 **PR #3 暂不合并**。当前发现以下 3 项合并前需要修正的问题：

### 1. 首页在“部分餐别无可行模板”时会出现空白

`components/home-screen.tsx` 当前早上使用 `breakfast && lunch && dinner` 才渲染整组内容，中午使用 `lunch && dinner` 才渲染。

当某个严格饮食条件导致其中一个餐别没有可行模板，但其他餐别仍有结果时，页面既不会显示已有餐食，也不会进入“全部为空”的提示，用户会看到“接下来怎么吃”下面空白。

要求：

- 每个餐别独立渲染，不要因为另一个餐别缺失而把已有方案一起隐藏。
- 缺失的餐别显示轻量、无责备提示，已有餐别照常显示。
- 增加回归测试或可验证的浏览器 smoke 场景。

### 2. “替换方案”可能绕过用户的饮食禁忌和现实条件

当前规划器只校验主模板是否满足禁忌、厨房能力、时间等条件，但 `MealTemplate.alternatives` 是模板中手写的字符串，未经同样约束过滤。

例如一个主方案本身符合素食/禁忌条件，其“替换方案”仍可能包含鱼、鸡蛋、奶制品、用户讨厌食物，或需要用户没有的厨房能力。这会导致主方案正确、替换方案错误。

要求：

- 替换方案必须来自同一套已通过当前 profile 约束的候选模板，或者在无法保证安全时不显示替换方案。
- 至少保证：饮食禁忌/讨厌食物、厨房能力、工作日准备时间不会被替换方案绕过。
- 如没有合法替换项，UI 应自然地不显示“替换方案”，不要输出 `undefined` 或无效占位。
- 增加自动测试：严格禁忌 profile 的主方案和替换方案都不能出现被禁止食物。

### 3. “纯素”判断漏掉了茶叶蛋等动物性食材表达

`lib/meal-planner.ts` 当前 `veganTerms` 使用了“鸡蛋”，但模板中存在“茶叶蛋”。字符串包含判断不会把“茶叶蛋”识别为“鸡蛋”，因此纯素用户仍可能获得“茶叶蛋 + 玉米 + 无糖豆浆”等方案。

要求：

- 修正纯素/全素动物性食材识别，至少覆盖当前模板池实际存在的动物性食材表达。
- 最好将此类约束结构化到模板标签/属性中，而不是继续依赖容易漏词的零散字符串判断；但不要为此做大型重构。
- 增加测试：纯素 profile 的主方案与合法替换方案不得包含当前模板池中的任何动物性食材。

## 已知问题 / 技术债

- 当前规划引擎仍是有限本地模板池和确定性规则，不是真实 AI，也没有完整营养计算。
- 预算、场景和食材成本是粗略估算，尚未接入个人长期食材环境模型或真实价格。
- profile、周方案、采购清单和每日反馈仍只存在当前浏览器，尚未跨设备同步。
- 重新完成建档会生成新方案并重置当前周采购清单，尚未支持历史周方案。
- 当前 `lint` 实际为 TypeScript `tsc --noEmit`，尚未配置 ESLint。
