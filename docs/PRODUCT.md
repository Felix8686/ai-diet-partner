# 产品指导文档（MVP）

## 定位

根据用户目标、预算和现实生活环境，帮助用户长期坚持饮食管理的 AI 伙伴。

不是 AI 菜谱生成器、卡路里记录器、健身打卡软件或冰箱库存管理工具。

## 核心用户

25–40 岁上班族，尤其是需要兼顾工作与家庭的人。MVP 以减脂/体重管理为主。

## 核心闭环

用户建档 → 建立现实饮食环境 → 生成一周可执行方案 → 采购建议 → 每日极简反馈 → 下一周调整 → 逐步形成个人饮食模型。

## 用户数据

- 身体与方向：年龄、性别、身高、体重、减脂/保持/改善健康等。
- 现实条件：预算、做饭时间、工作日/周末差异、外食比例、食堂/外卖/便利店。
- 厨房能力：炒、煮、蒸、微波、电饭锅、空气炸锅、烤箱等。
- 饮食偏好：喜欢/讨厌、禁忌、早餐困难、夜宵、零食等。
- 个人食材环境：用户生活范围内长期能买到什么、价格如何、是否稳定。

## 个人食材环境模型

它不是全国商品库，也不是冰箱库存。它描述“这个用户现实中长期可以买到什么”。

MVP 数据采集以购物小票识别为主，超市货架拍摄作为冷启动辅助。UI 可称“我的食材”或“常买食材”。

## 每日反馈

约 30 秒：计划执行情况、零食情况、偏离原因（没时间、太麻烦、买不到、太贵、不喜欢、临时聚餐等）。

产品关注的不是“你有没有做到”，而是“为什么没做到，下一次怎样更容易做到”。

## AI 规划链路

用户资料 → 目标/营养计算 → 现实条件过滤 → 食材匹配 → AI 生成 → 执行风险检查 → 最终方案。

生成后必须再次检查预算、厨具、制作时间、忌口/不喜欢、食材可得性、重复程度和外食场景。

## 页面

### 首页

只回答“接下来怎么吃”。按时间动态展示当前餐、下一餐和必要预览；晚间再出现极简反馈。

### 3 步建档

1. 身体与方向
2. 日常生活条件
3. 饮食与购物环境

### 本周方案

横向日期栏 + 当前日期详情。避免“本周目标”“预计减重”等压力表达，可使用“这周怎么吃”。

### 采购清单

只提供已买/未买。不要扩展成库存管理。

## 技术路线

Web App / PWA 优先，验证成功后再考虑微信小程序，最后才考虑原生 App。

建议栈：Next.js + TypeScript + Supabase/PostgreSQL + 可替换 AI Provider + 独立规则层。
